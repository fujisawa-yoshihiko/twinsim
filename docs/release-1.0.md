# twinsim 1.0

[English](release-1.0.en.md)

建物の人流のシミュレータの最初の版。設定は JSON で、Python から呼べる。

## 1.0 に入っているもの

- JSON の設定、Python のライブラリ、コマンド、GUI
- 正解データ（軌跡・状態・カメラの枠・集計・グラフ）と、Isaac Sim での描画
- [チュートリアル](config-tutorial.md)、[リファレンス](config-reference.md)、[コードの例](../examples/README.md)
- 人の現れる場所の座標指定、GUI での発生位置とカメラの編集

## 前の版からの大事な修正

| 修正 | 影響 |
|---|---|
| 動画に 1 コマ多く入っていた | 3 コマ目あたりから動画が正解より 1 コマ遅れていた。これから描く動画は全部のコマが正解とそろう。**0.x で描いた動画はそのまま**で、1 コマ遅れている |
| 書いた分布に既定の `min`・`max` が混ざっていた | 速さなどの分布が黙って切られていた |
| 床の高さが 0 でない空間で枠がずれていた | `simple_room` と、自分で作った空間 |
| 設定の名前からファイルの外へ書けた・Isaac Sim の中で動いた | `name` とカメラの名前は文字・数字・`_`・`-` だけにした |
| GUI にスクリプトを入れられた | 表示を全部エスケープし、CSP を足した |
| 同じ場所に計算し直すと、古いカメラのラベルが残った | 前の結果を置き換えるようにした |

## 既知の制限

- 混んだゲートの近くで、軌跡が 1 コマで最大約 1 m 跳ぶことがある（`verify_gate_capacity` で全ステップの約 0.3%）。歩き方のエンジンの近似で、直すと文献との比較を全部やり直すことになるので、1.0 では残した。
- カメラの `clock_offset_s`・`drop_rate` は記録だけで、動画と正解に反映しない。
- 人の枠は箱を映した近似で、画面の外へはみ出す値もそのまま書く。
- `gate_events` の時刻は、列の先頭が動き出す時刻（通過の 0.4〜0.7 秒前）。
- `boarded` には、計算の終わりまでに乗り切れなかった人も入る。
- 行き先は場所の名前だけで、座標では書けない。

## 確かめたこと

- 自動テスト、チュートリアルの全部の JSON の実行、全テンプレートの実行
- クリーンな環境（Python 3.10・3.13）への wheel のインストール
- 同じ設定と seed で同じ結果（プロセス・Python の版をまたいで一致）
- GUI をブラウザで操作（CSP を有効にしたまま）
- ファイルと全履歴の秘密の情報の検査、依存パッケージの脆弱性の検査
